# 主人账本备份恢复验收

当前原生客户端增加完整主人账本的导出、检查与恢复。入口在「我的 Agent → 账本备份」，操作本设备上当前登录主人的账本。恢复写入空账本，拒绝覆盖已有费用、审批或请求，恢复后不启动 Agent 服务。

分支 `codex/agent-capabilities` 以重新拉取的 main `42e59b9e` 和 A1 编程执行提交为基础。A1 的后续跨平台修正同时推送到原编程分支；账本能力单独提交。原源码工作区的其他修改保留。

## 使用与边界

导出时输入新的完整文件路径，点击「导出新备份」。文件从创建起使用当前操作系统用户的私有权限，已有文件或符号链接不被覆盖。检查或恢复可以使用「选择备份」打开原生文件选择器，也可以输入路径。检查后显示主人、UTC 保存时间、请求数、未决调用和待发送回复；确认后恢复绑定同一文件摘要。

恢复前停止当前主人的全部 Agent 服务。目标必须是同一服务器、issuer、subject 和 Matrix 主人的空账本。不能通过恢复旧备份清除较新记录；已有记录的设备会收到明确拒绝。损坏的现有数据库也不会被静默覆盖，应在空的恢复设备上操作。启动恢复后的 Agent 时仍执行原有服务器执行历史校验；备份缺少服务器上的记录时继续阻塞模型执行。

备份包含账本所有表：模型与策略、三层费用和预留、调用、原始执行和回复、审批消费状态、模型会话引用和容量配置。不会复制账本外的 provider 登录文件、Matrix 登录文件、设备密钥、Agent 工作目录内容或服务自动启动意图。模型和工作目录引用在恢复设备上仍需检查可用性。

文件格式包含版本、身份、时间、数据库摘要与原始 SQLite 页面镜像。SHA256 用于检测损坏及绑定检查结果，不是备份签名或文件加密；备份中的请求和回复需由主人妥善保管。本版要求当前账本结构，其他版本明确拒绝。

## 实现保证

- 在线备份使用同一个只读 SQLite 事务，包含已提交 WAL 页面，不复制活跃数据库及 sidecar 文件；复制前后限制大小为 128 MiB。
- 发布前使用与导入相同的解码、结构、SQLite 完整性、外键、精确身份和摘要检查。检查不创建磁盘数据库。
- 原生命令只在进程内接受本地路径，没有公开 HTTP 或远程配置入口。管理调用锁覆盖整个恢复过程，恢复前再次检查当前设备身份和运行状态。
- 恢复在单个 IMMEDIATE 事务中插入全量记录，提交前再次检查有限授权。撤销或异常会回滚全部插入；不替换当前数据库文件或丢弃 WAL。
- 保留原始未决状态、费用、预留、回复和审批消费状态，不产生 provider 或 Matrix 调用来重新生成结果。后续运行遵循已有恢复和历史覆盖规则。
- 文件选择回调绑定账号及请求序号，并保留选择器临时文件的生命周期；编辑路径会清除检查结果及恢复确认。
