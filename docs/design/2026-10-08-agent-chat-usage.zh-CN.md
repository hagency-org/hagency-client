# Agent 聊天用量与配额反馈

> 2026-10-28 更新：按用户决定与资源池 Agent 统一，个人 Agent 的回复只包含答案，不再追加“本轮处理已结束 / 本次用量”摘要和主人私聊的“Agent 配额”行。本次用量和额度在账本与 Agent 限额页查看。未调用模型的处理说明（未授权、额度不足、历史费用待确认）保留。Desktop 的 `agent_usage` 展示逻辑只处理历史消息中的旧摘要。下文为 10-08 的原始设计记录。

## 差异核对

旧 Rinx 展示的处理状态不是聊天界面自行计算的。旧客户端 `hagency-store/domain/activity.rs` 投影执行生命周期、时间与工具事件，再由 `hagency-matrix/outgoing.rs` 发送并编辑 Matrix notice。旧配额暂停提示由 `domain/quota_holds.rs` 生成。

当前设备执行模型已经替换这条路径：Codex 适配器正常结算输入、输出、缓存输入、推理输出用量，但 `owned_runtime::run_turn` 原先仅保存 `completed.text`，所以聊天没有用量信息。预算不足、权限拒绝、历史费用未知又统一上报 Rejected，聊天看起来没有回应。Desktop 仍能正常渲染普通文字和 notice；断点在生成与发送端。

## 本次实现

每次成功完成的答案末尾增加持久摘要，例如：

```text
✅ 本轮处理已结束 · 已运行 13 秒
本次用量 50 Token（输入 30 / 输出 20；缓存输入 10，推理输出 5）· 工具请求 2 次，已返回 1 次
```

- 用量取 Codex 同一 thread/turn 的实际 cumulative-counter 增量，原有结算与累计基线保持同一事务。缓存输入属于输入，推理输出属于输出，不再相加。
- 耗时从发送 `turn/start` 开始，到收到该 turn 的终止事件为止，包含工具等待时间，不包含账号检测和上下文初始化。
- 工具 item 按本轮 ID 去重；动态宿主工具在实际 `item/tool/call` 请求和回应边界计数，忽略对应 dynamicToolCall item，避免重复。返回可表示成功、失败或拒绝，不能据此认定已产生工具效果。普通答案、推理 item 和审批本身不算工具调用。
- 摘要与答案合并后先落入本地不可变回复，再使用现有服务器 outbox/Matrix 事务发送。重试、重启与续租恢复使用原正文和摘要，不再次运行模型，也不重算当时耗时。
- 64 KiB 是字节上限；极长答案按 UTF-8 边界显式截断，保留用量摘要。额外预留 1 KiB 给主人私聊的额度信息。

仅在服务器确认的主人私聊绑定中，额外显示 Agent 总额度：对应累计、UTC 当日或 UTC 当月的已用量、上限，以及运行中或待确认的预留。共享 Room 只显示本次用量，不公开跨 Room 的 Agent 总预算和消耗。

## 无模型处理提示

请求未获授权、配额未配置或不足、历史费用待确认分别有明确说明。本次未调用模型时，提示也通过同一持久回复链路发送。

新增 `persist_no_provider_reply` 仅允许精确已确认 running 的 execution 且不存在该 execution 的模型调用记录。零调用证明与固定回复在一个 SQLite IMMEDIATE 事务中写入。已有 pending、unknown 或 settled 模型调用不能改成零调用；其他请求的未知费用和预留不得改变。历史恢复同时识别这种证明，并继续校验整个账本余额。第一次模型调用费用未知时仍按原逻辑保留未知结果和预留，不伪造完成、Token 数或零费用；之后被此费用阻止的新请求可以收到未调用模型的说明。

## 展示范围

本次恢复的是完成后的摘要及处理阻止说明，旧聊天消息不会被改写。旧版单独可编辑 notice 的实时“处理中／等待审批”刷新尚未迁入当前 Appservice outbox；本次不声称恢复了实时进度消息。所有输出仍通过当前服务器身份、设备、lease、dispatch 和回复摘要校验，没有恢复旧 Fleet／Engagement 数据结构。

已结算用量的失败／中断 turn 仍按原逻辑上报 Failed，尚不发送完成摘要；超时或未知结果仍保留预留，也不生成假用量。不能将本次完成摘要称为所有终态的状态通知。

## Desktop 信息按钮（后续界面调整）

成功回复默认只显示答案；发送者名字同行、名字后方显示一个小用量柱状图标，不显示 Info 或“信息”文字。图标为 14px，按钮命中区为 24px，保留悬停说明。点击展开或收起答案下方的详情，文字使用主题灰色与较小字号（9 × text scale，低于正文）。详情压缩为耗时／Token／工具返回数、输入输出明细、可选主人额度三个短行。错误、暂停和不完整统计原文保持直接可见，不纳入成功统计折叠。

这是展示层调整，原 Matrix 正文、用量账本、重试摘要及复制／转发内容均保持完整。只识别 Hagency Appservice 傀儡发来的精确完整完成后缀，并校验数字一致性；普通用户引用类似文字、格式不匹配或 rich HTML 消息不剥离。默认 standalone 构建及可选 agent_chat 构建均支持，移动／紧凑消息模板也有对应入口。

展开状态按账号、Room、事件分别保留，并在注销或切换会话时清除；虚拟列表复用消息 widget 时重新设置身份与详情。普通引用、SDK 线程预览、raw-event 线程缓存及聊天列表的最新消息预览均剥离成功统计后缀，避免短答案的预览被统计占满。

专项回归覆盖精确后缀与数字校验、暂停／错误可见、私人额度、重复后缀、widget 回收和会话隔离、姓名行与详情共享展开状态及收起不留空白、raw／SDK 预览一致性及原 SDK 正文不变。Desktop 全部 347 项通过、1 项原有忽略；默认构建与可选 agent_chat 编译检查通过。新增展示逻辑已经独立只读复审。
