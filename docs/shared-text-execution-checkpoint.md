# Native shared text execution checkpoint

This default-disabled slice pairs central shared-work schema 13 with owner-ledger schema 80. It authorizes one text-only turn on one retained, freshly qualified process. It does not enable production execution, successive turns, a replacement process after uncertainty, grant renewal after a device-generation change, or unproven usage settlement.

The trusted Desktop host uses `AdoptedManagementSelection::shared_executor` to obtain a sealed `AdoptedSharedExecutor`. It owns the canonical registry and original private journals internally. The factory and every poll/recovery entry require current SDK authority, the original installation/device, the adopted source selection, and the native host epoch gate. The dedicated session receives only `ExecuteManagedAgents`; no mini-app service acquires that permission. `shared-execution` is a separate Cargo feature and is not implied by onboarding.

The native transport accepts only closed central runtime/work routes and canonical command digests. Fresh runtime delivery returns one-shot process custody. Historical delivery cannot recreate it. The existing canonical resource/project/agent budget chain reserves the first call's remaining child balance once. Native persists the original input before acknowledgement and records a start attempt before contacting central. A lost or non-fresh start reply never runs the model.

The retained process rechecks its effective no-tools configuration and authenticated provider quota identity, then receives the exact saved text body. The actual process source records that input digest. Activity renewal updates the same process and original pending event read; it cannot revive an expired source or substitute a successor. The deadline remains the minimum of its original monotonic bound, current authenticated lease, native profile gate and conservative wall-time bound. Millisecond wall sampling may shorten that bound, but cannot extend it.

Output and cumulative per-call usage are written before upload. Fresh input, cache-write input and output are charged without charging cache-read twice. Oversized escaped output is omitted without discarding usage. Terminal output does not prove complete usage. Overruns and unknown consumption remain held. Central owns the durable threaded Matrix reply; native keeps the original process alive while that reply is pending.

Restart reconciliation discovers only the original runtime's bounded saved work IDs and uploads exact existing observations. A newer local stop receipt is uploaded before treating an older central qualified projection as current. Missing evidence never recreates a model invocation. Stop evidence is separate from usage completeness and cannot free an unknown call hold.

The Desktop worker advances the opaque circular discovery cursor for returned original commands and retains its poll task across cancellation. Native owner retirement closes execution before worker drain; native shutdown separately drains retained process custody. Runtime/client tests use explicit offline supervised probe children. No actual provider prompt has been issued for this checkpoint.

## Validation and current limits

The earlier owner-store regression run passed 240 tests (5 explicit probes ignored), and the runtime supervised suite passed 12 tests. Final focused store tests pass 11/11. The loopback HTTP, canonical SQLite and supervised-child bridge suite passes 9/9, including lost starts/results, restart receipts, wrong input, logout, cancellation and renewal while the original event read is pending. The original three-process adoption handoff and host-epoch-before-agent-commit tests each pass. The exact immutable20 plus bridge overlay independently passes all nine bridge tests and the handoff test. Strict native default and enabled-feature Clippy, and store all-target Clippy, pass. The exact overlay test lint additionally uses the separate reconnect regression layer, because immutable20 contained its test helper without the test caller. Earlier failed runs and the red/green deadline regression are retained in `.run/shared-text-execution-checkpoint/manifest.json`; no actual provider prompt is claimed.

The first checkpoint is deliberately one turn per original runtime. Historical work-report failure can delay reporting a later process stop; both remain durably recorded locally. Production multi-turn support must separate those reconciliation queues and add bounded paging rather than infer settlement from stopped processes. A device-generation change requires the existing explicit contribution reconnect, and a previously published immutable grant needs a separate reviewed revision/renewal protocol before fresh allocations can resume. Neither limitation is bypassed here.
